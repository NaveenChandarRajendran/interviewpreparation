# Java Execution Flow

## Java Architecture

```text
JDK
 └── JRE
      └── JVM
```

### JDK (Java Development Kit)

Used to **develop** Java applications.

It contains:

- JRE
- Compiler (`javac`)
- Debugger
- Development tools

**Responsibilities:**
- Write Java code
- Compile Java code
- Run Java applications
- Debug applications

---

### JRE (Java Runtime Environment)

Used to **run** Java applications.

It contains:

- JVM
- Java standard libraries

**Responsibilities:**
- Provides the environment required to execute Java applications.
- Does **not** contain the Java compiler (`javac`).

---

### JVM (Java Virtual Machine)

The JVM is responsible for **executing Java bytecode**.

**Responsibilities:**

- Loads classes into memory.
- Verifies bytecode for security.
- Converts bytecode into machine code.
- Manages memory.
- Performs Garbage Collection.

---

# Java Program Execution Flow

Suppose we have:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello World");
    }

}
```

## Step 1 - Write Java Code

Create a Java source file:

```text
Main.java
```

---

## Step 2 - Compile

Run:

```bash
javac Main.java
```

Compiler converts:

```text
Main.java
        ↓
Main.class
```

The `.class` file contains **Bytecode**.

---

## What is Bytecode?

Bytecode is an intermediate language generated by the Java compiler.

It is **not machine code**.

Only the JVM understands Bytecode.

```text
Java Code
      ↓
Compiler (javac)
      ↓
Bytecode (.class)
      ↓
JVM
      ↓
Machine Code
```

---

## Why Bytecode?

Different operating systems use different machine code.

Instead of generating machine code directly, Java generates Bytecode.

Each operating system has its own JVM.

```text
Windows
    JVM
     ↓
Machine Code

Linux
   JVM
    ↓
Machine Code

Mac
  JVM
   ↓
Machine Code
```

The same `.class` file runs on every operating system.

**This is why Java is platform independent.**

---

## Step 3 - Run the Program

Execute:

```bash
java Main
```

JVM starts executing the program.

Execution flow:

```text
Main.class
      ↓
Class Loader
      ↓
Bytecode Verifier
      ↓
Execution Engine
      ↓
Machine Code
      ↓
CPU
```

---

# Class Loader

The Class Loader loads required classes into JVM memory.

Example:

```java
ArrayList<String> list = new ArrayList<>();
```

When `ArrayList` is used, JVM loads the `ArrayList` class.

It does **not** load every Java class during startup.

**Benefit:**
- Saves memory.
- Faster startup.

---

# Bytecode Verifier

Before execution, JVM verifies the bytecode.

Checks include:

- Valid bytecode
- Memory safety
- Stack correctness
- Illegal operations

If verification fails, execution is stopped.

**Benefit:**
- Improves application security.

---

# Execution Engine

The Execution Engine converts Bytecode into Machine Code.

It uses two components:

## Interpreter

- Reads Bytecode line by line.
- Executes one instruction at a time.
- Slower.

---

## JIT (Just-In-Time) Compiler

If a method is executed many times, JVM compiles it into native machine code.

Future executions run directly using machine code.

**Benefit:**
- Improves application performance.

---

# Complete Java Execution Flow

```text
Main.java
      ↓
javac
      ↓
Main.class (Bytecode)
      ↓
java Main
      ↓
JVM Starts
      ↓
Class Loader
      ↓
Bytecode Verifier
      ↓
Execution Engine
      ↓
Interpreter / JIT Compiler
      ↓
Machine Code
      ↓
CPU Executes
```

---

# Development vs Runtime

## During Development

Install **JDK**.

```text
JDK
├── javac
├── Debugger
├── Development Tools
└── JRE
     ├── JVM
     └── Java Libraries
```

Developers need JDK because they:

- Write code
- Compile code
- Run code
- Debug code

---

## During Runtime

When executing:

```bash
java Main
```

Only the runtime components are used.

```text
JDK
   ↓
JRE
   ↓
JVM
   ↓
Runs the application
```

The compiler (`javac`) is **not used** while running the program.

---

# Production Server

The application is already compiled.

No compilation happens on the server.

Traditionally:

```text
JRE
   ↓
JVM
   ↓
Runs the application
```

Modern Java (Java 11+) no longer provides a separate JRE download.

Most production servers install the **JDK**, but only the runtime (JVM + libraries) is used to execute the application.

---

# Key Interview Points

- **JDK** → Used for development. Contains JRE, compiler (`javac`), debugger, and development tools.
- **JRE** → Runtime environment. Contains JVM and Java libraries.
- **JVM** → Executes Java Bytecode.
- **Bytecode** → Intermediate code generated by the compiler (`.class` file).
- **Compiler (`javac`)** → Converts `.java` to `.class`.
- **Class Loader** → Loads required classes into memory.
- **Bytecode Verifier** → Validates bytecode before execution.
- **Execution Engine** → Executes bytecode using the Interpreter and JIT Compiler.
- **Interpreter** → Executes bytecode line by line.
- **JIT Compiler** → Converts frequently executed bytecode into native machine code for better performance.
- **Platform Independence** → Same `.class` file runs on any operating system that has a compatible JVM.
